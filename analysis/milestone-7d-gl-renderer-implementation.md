# Milestone 7D: Weston 14.0.2 Direct-DECON GL Renderer Implementation

## 1. Executive Summary

Milestone 7D delivers full OpenGL ES 3.2 hardware-accelerated scene compositing for Weston 14.0.2 on the Samsung Galaxy A30 (`SM-A305F`, Exynos 7904, ARM Mali-G71 MP2) using an in-tree Direct-DECON backend linked to proprietary Mali DDK r26p0 via `libhybris`.

Unlike standalone GPU test applications or CPU Pixman copy pipelines, this milestone achieves:
1. **Compositor GPU Scene Rendering**: Weston's compositor scene graph (including desktop shell, client surfaces, input cursors, and damage tracking) is rendered directly by the ARM Mali-G71 GPU using OpenGL ES 3.2 shaders. Compositor render time dropped from ~66.2 ms (CPU Pixman) to **0.90 ms - 3.89 ms** (Mali GPU).
2. **Zero-Copy DECON Presentation**: Composed frames are output to an `EGLSurface` backed by a `libhybris` `ANativeWindow` (`HWCNativeWindow`). Upon `eglSwapBuffers()`, the underlying Gralloc ION DMA-BUF file descriptor is passed directly to Samsung Exynos DECON Window 3 / IDMA channel 0 via `S3CFB_WIN_CONFIG_IOCTL` without intermediate CPU copies.
3. **Dual-Fence Asynchronous Pacing**: GPU acquire fences generated by `eglSwapBuffers()` are submitted to the DECON driver to guarantee GPU completion before scanout. Composite retire fences returned by DECON (`win_data.fence`) are handed back to Gralloc to guard buffer reuse and registered with the Wayland event loop (`wl_event_loop_add_fd`) to lock compositor repaint scheduling to the physical EA8076 Super AMOLED 60 Hz VSYNC clock.
4. **Resilient Downstream Compatibility**: Upstream Weston's `renderer-gl/egl-glue.c` assertion crash on non-GBM/surfaceless platforms was resolved, enabling seamless operation under Android EGL platforms (`EGL_PLATFORM_ANDROID_KHR` and legacy `eglGetDisplay`).
5. **Preserved Pixman Fallback**: The proven CPU Pixman -> ION -> DECON fallback remains intact and selectable via `--renderer=pixman` or `--use-pixman`.

## 4. Upstream Weston Bugs & Bridge Resolutions

### 4.1 Upstream EGL Platform Assertion Failure (`egl-glue.c`)
- **Problem**: Upstream Weston's `platform_to_extension(EGLenum platform)` strictly switched on GBM, Wayland, X11, and Surfaceless platforms. Any other enum triggered an immediate abort (`assert(0 && "bad EGL platform enum")`). When passing `EGL_PLATFORM_ANDROID_KHR` (`0x3141`) or `0` (default display), the compositor crashed on startup.
- **Fix**:
  1. Extended `platform_to_extension` to handle `EGL_PLATFORM_ANDROID_KHR` returning `"android"` and `0` returning `NULL`.
  2. Updated `gl_renderer_setup_egl_client_extensions()` to gracefully skip `EGL_KHR_platform_*` checks when `extension_suffix == NULL`.
  3. Updated `gl_renderer_setup_egl_display()` to only call `gr->get_platform_display()` when `gr->has_platform_base && gr->platform != 0`, cleanly falling back to `eglGetDisplay(native_display)`.

### 4.2 Libhybris Window Teardown Double-Free Bug
- **Problem**: In `hwcomposer_window.cpp`, `HWCNativeWindow` maintains a reference count tied to the underlying `EGLSurface`. When `ec->renderer->gl->output_destroy()` invoked `eglDestroySurface()`, EGL decremented the window reference count to 0, which automatically invoked `delete window`. A subsequent explicit call to `HWCNativeWindowDestroy(output->native_window)` executed a secondary `delete window` on already freed memory, generating a `SIGSEGV` during compositor shutdown.
- **Fix**: Removed explicit `HWCNativeWindowDestroy()` calls from normal output teardown paths. `HWCNativeWindowDestroy()` is now strictly retained as an error-path destructor if `gl->output_window_create()` fails prior to surface creation.

### 4.3 Musl-Safe Bionic Structure Isolation
- **Problem**: Attempting to include Android Bionic headers (`<android/nativebase/nativebase.h>`, `<system/window.h>`) inside the DECON backend triggered compilation failures under musl libc due to deprecated non-standard `#include <sys/cdefs.h>` and missing Android include search paths (`<system/graphics-base.h>`).
- **Fix**: Cleanly defined the exact ABI memory layout of `native_handle_t`, `struct android_native_base_t`, and `struct ANativeWindowBuffer` inside `decon_internal.h`, eliminating all external Bionic header dependencies while guaranteeing 100% binary compatibility with libhybris.
